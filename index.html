Value Proposition

An automated web security workflow

Auspex brings proxy-list ingestion, crawling, modular checks, finding-based analysis, relevant exploit-validation attempts, and reporting into one workflow. Successful checks can trigger automatic evidence and loot collection. False-positive reduction has been a focus of testing, but results still require review and can vary by target.

62 Security Modules

A broad set of web and API security checks runs as part of one configured assessment. Module coverage and results depend on the target and scan settings.

🌐

Timeout-aware checks

Requests and modules use time limits. A timed-out check may be incomplete or skipped, and should be reviewed in the final results.

⏳

Timeout-aware module queue

The UI exposes a scan-time setting, while completion mode can run beyond that value to allow the module queue to progress. Individual modules have their own timeouts; a timed-out check may be incomplete while later checks continue.

🔒

Finding-based validation and loot

Auspex analyzes findings, selects relevant checks, and attempts validation. When a check succeeds, follow-up evidence or loot collection can run automatically. JWT-related checks can lead to API discovery and data-retrieval attempts; complete database extraction is not guaranteed.

🚀

Autonomous Mode

After the target and settings are entered, the workflow proceeds without routine operator input. Use only against systems you own or are explicitly authorized to assess.

📍

False-Positive Hardening

Baseline comparisons and response checks help reduce false positives. They do not eliminate them, so findings should be reviewed before being treated as confirmed.
