62 Security Modules

A broad set of web and API security checks runs as part of one configured assessment. Module coverage and results depend on the target and scan settings.

🌐

Timeout-aware checks

Requests and modules use time limits. A timed-out check may be incomplete or skipped, and should be reviewed in the final results.

⏳

Timeout-aware module queue

The UI exposes a scan-time setting, while completion mode can run beyond that value to allow the module queue to progress. Individual modules have their own timeouts; a timed-out check may be incomplete while later checks continue.

🔒

Finding-based validation and loot

Auspex analyzes findings, selects relevant checks, and attempts validation. When a check succeeds, follow-up evidence or loot collection can run automatically. JWT-related checks can lead to API discovery and data-retrieval attempts; complete database extraction is not guaranteed.

🚀

Autonomous Mode

After the target and settings are entered, the workflow proceeds without routine operator input. Use only against systems you own or are explicitly authorized to assess.

📍

False-Positive Hardening

Baseline comparisons and response checks help reduce false positives. They do not eliminate them, so findings should be reviewed before being treated as confirmed.

Workflow & Supporting Components

Proxy intake and preflight

Can load locally available proxy lists and check proxy connectivity before the assessment. Availability and exit-IP verification depend on the supplied proxies and network conditions.

Crawl and surface discovery

Begins with the configured website, discovers links, forms, parameters, and API-related paths, and feeds discovered inputs into relevant checks. Optional authentication can enable an additional crawl pass.

Static data discovery

Inspects reachable page state, browser storage, JavaScript/source-map assets, framework data, and discoverable files. It may identify exposed data or additional backend URLs; it cannot guarantee access to private data.

Dynamic backend/API pass

A separate dynamic backend phase follows the static discovery phase and the main module checks. It examines reachable application/API behavior and may use eligible discovered evidence for follow-up. It is an additional phase, not only a fallback triggered when static discovery finds nothing.

Analysis and validation

Findings are analyzed and prioritized. Eligible findings can trigger relevant validation attempts; checks may fail or time out, and results should be reviewed before being treated as confirmed.

Conditional collection and reports

When authorized validation paths yield accessible evidence, follow-up collection and an evidence archive may run. Scan results and reports are produced for review; complete database extraction is not guaranteed.

The workflow is designed for systems you own or are explicitly authorized to assess. Time limits, access controls, rate limits, and target behavior can leave individual checks incomplete.
